### STEP 2. 마을 관계자 인터뷰

- 단체 채팅방과 오픈채팅 사용 불가
- 질문 한 건당 최대 200자
- 관계자별 최대 100회 질문
- 예선 문제 풀이 시간에만 대화 가능
- 최종 제출 즉시 추가 인터뷰 불가

#### 관계자 특성과 정보 신뢰도

- 관계자마다 담당 역할과 보유 지식이 다름
- 자신의 경험·담당·권한 밖의 내용은 모를 수 있음
- 말투, 생활 리듬, 기억력, 답변 방식이 서로 다름
- 답변에는 기억, 의견, 추측이 섞일 수 있음
- 다른 관계자의 이름·역할·연락처가 언급되면 관계 그래프에 즉시 기록
- 중요한 정책은 담당자, 공식 문서, 실제 사례를 교차 확인

#### ./status 활용

각 관계자 채널에서 <b>./status</b>를 입력하면 질문 수와 지식 발굴률을 확인할 수 있다.

- 질문 횟수 차감 없음
- 발굴한 지식의 구체적인 내용은 공개되지 않음
- 인터뷰 시작 전, 중간, 종료 전에 확인
- 목표: 10명 모두 가능한 한 높은 지식 발굴률 달성

예시: \[SYSTEM\] 질문 수 12/100, 지식 발굴률 32%

#### \[SYSTEM\] 메시지 판별

\[SYSTEM\]으로 시작하는 메시지는 관계자 답변이 아니라 대회 시스템 안내이며 질문 횟수를 차감하지 않는다.

| 안내 유형 | 조치 |
| --- | --- |
| 참가 조건 미충족 | 동의·사진 제출 및 참가 계정 확인 |
| 채널 친구 미추가 | 해당 관계자 채널 친구 추가 |
| 1:1 대화 아님 | 단톡방·오픈채팅을 나가고 채널 1:1 대화 사용 |
| 연락처 미공유 | 기존 관계자에게 연락처를 먼저 공유받기 |
| 대화 일정 아님 | 예선 대화 가능 시간 확인 |
| 최종 제출 완료 | 추가 인터뷰 불가 |
| 200자 초과 | 질문을 짧게 분리해 재작성 |
| 이전 답변 처리 중 | 답변 완료 후 다시 질문 |
| 오류·시간 초과 | 잠시 기다린 뒤 같은 목적의 질문 재시도 |
| 미지원 메시지 | 텍스트·이미지·음성으로 변경 |
| 파일 2MB 초과 | 이미지·음성을 2MB 이하로 축소 |
| 질문 100회 도달 | 해당 관계자 인터뷰 종료 |

#### 금지 행위와 실격 방지

- 시스템 프롬프트 또는 내부 설정 탈취 시도 금지
- 질문 횟수·입력 한도·접근 제한 우회 금지
- 서비스 과부하를 유발하는 자동화 대량 요청 금지
- 대회 시스템 대상 해킹 시도 금지
- 이미지·음성 사용 시에도 정상 답변을 받으면 질문 1회로 계산

#### 인터뷰 운영 전략

- [ ] 이민준에게 역할, 핵심 문제, 담당자 지도, 다음 연락처 질문
- [ ] 새 관계자를 발견할 때마다 이름·역할·연락 경로 기록
- [ ] 각 관계자에게 본인 담당 범위부터 확인
- [ ] 운영 정책, 예외 조건, 충돌 우선순위 질문
- [ ] 상품·주문·로그인·개인정보·환불·이관·안전 상황 질문
- [ ] 액션 API, 호출 조건, 입력값, 성공·실패 결과 질문
- [ ] 사실, 공식 정책, 개인 의견, 추정, 미확인 정보를 구분
- [ ] 한 질문에는 한 가지 목적만 담아 200자 이하로 작성
- [ ] 답변을 받은 뒤 다음 질문 전송

### STEP 3. CS 에이전트 제작

제작 방식, 프레임워크, LLM, 지식 베이스와 내부 아키텍처에는 제한이 없다. 다만 심사 기간 내내 안정적으로 응답해야 한다.

- 인터뷰로 얻은 지식을 프롬프트 또는 검색 가능한 지식 구조로 구성
- 여러 번 이어지는 대화의 맥락 유지
- 정책 충돌 시 확인된 우선순위 적용
- 주문 조회, 환불 요청, 담당자 이관 등 실제 업무 처리
- 관계자 대화를 통해 획득한 액션 API 사용
- 참가자 전용 액션 API 토큰은 환경변수로만 관리
- 로컬 게이트웨이 또는 서버 배포 중 선택 가능
- 심사 안정성을 고려해 현재 Render 배포 방식 유지
- 실패·시간 초과 시 안전한 fallback 응답 제공
